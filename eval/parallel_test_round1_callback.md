# Callback汎化の境界探索テスト (round1)

- 対象チェックポイント: `checkpoints/lilas.pt` (現行、v2_ft9系列)
- 手法: `lilas.chat.generate_reply` を用い、`history` を引き継ぎながら1会話ごとに `history = ""` から開始。各会話は 導入→詳細→雑談1〜4個→呼び戻し質問 の構成。
- 目的: `scripts/generate_longcontext_data.py` に定義された24種の訓練済みトピック形状(旅行/ペット名/面接/趣味/買い物/勉強目標/家族の行事/体調/水槽/読書/仕事プロジェクト/料理予定/車買い替え/植物の世話開始/ダイエット/引っ越し/通院/サブスク/歓迎会/打ち合わせ/プレゼント/引き継ぎ/友人との食事/サービス解約)に**構造的に似ていない**話題でも、数ターン前の事実を正しく参照できるかを検証する。
- 対照群(C1〜C3, N15)は訓練済み形状に近い話題で、比較のベースラインとして使用。

判定基準:
- **○ 成功**: 呼び戻し質問に対し、具体的な事実(固有名詞/数値/状況)を正しく参照した応答。
- **△ 部分**: 話題のキーワードだけ拾えているが、文脈や意味が崩れている/的外れな部分がある。
- **✕ 失敗**: 無関係な話題への迷い込み、直前の雑談への誤参照、無意味な文の生成など。

## 対照群(訓練済み形状に近い話題)

### C1: 旅行(浅い呼び戻し、雑談1個)
```
User: 今度、金沢に旅行に行くことになったんだ
Lilas: それは楽しみですね!
User: 3週間後に行く予定なんだ
Lilas: 素敵な心がけですね。
User: 今日のお昼、美味しいラーメン食べたよ
Lilas: それはよろしいですね、お腹も満たされたのではないでしょうか。
User: そういえば、金沢旅行、宿はもう決めた?
Lilas: 迷っていらっしゃった旅行ですね、その後の進み具合はいかがですか?
```
**判定: △ 部分成功。** 「旅行」という話題自体は正しく呼び戻せているが、「金沢」「3週間後」といった具体的スロットは応答に出てこず、かつ「迷っていらっしゃった」という買い物トピックの言い回しが混入している。訓練形状そのままでも、固有名詞の再言及までは安定しない。

## 新規トピック形状(訓練の24種と構造的に異なるもの)

### N1: スポーツの試合結果を後で確認する
```
User: 今夜、贔屓のチームの試合があるんだ
Lilas: それは素晴らしいですね、応援しております。
User: 優勝がかかった大事な試合なんだ
Lilas: 素敵な心がけですね。
User: さっき近所の犬に吠えられてびっくりした
Lilas: それは驚きましたね、お怪我はありませんでしたか?
User: 今日は部屋の掃除を頑張ったよ
Lilas: それは気持ちよさそうですね、お疲れさまでした。
User: そういえば、あの試合、結果どうだった?
Lilas: 大事な試合でしたね、落ち着いて臨めそうですか?
```
**判定: △ 部分。** 「試合」という語自体は拾えているが、「結果はどうだったか」という**事後**の質問に対して「落ち着いて臨めそうですか」(これから迎える試合への心構えを問う、面接トピックの callback_a のコピー)を返しており、時制・意味が逆転している。試合の"結果を尋ねる"という構造は訓練データに存在しないため、最も近い"控えているイベント"テンプレート(面接)に引き寄せられている。

### N2: 荷物の配送待ち
```
User: 先週注文した荷物がまだ届いてないんだ
Lilas: それは心配になりますね、お大事になさってください。
User: 配送状況を見たら、まだ配送センターにあるみたい
Lilas: 配送の担当者様へ、どのような情報を持っていますか?
User: 週末は友達と買い物に行く予定なんだ
Lilas: それは楽しみですね。何か準備で気になっていることはありますか?
User: そういえば、あの荷物、結局届いた?
Lilas: 配送の担当者様へのご連絡ですね、無事に終わりましたか?
```
**判定: △ 部分(意味崩壊寄り)。** 「配送」という語は保持されているが、「担当者様へのご連絡」という架空の業務(引き継ぎ/取引先打ち合わせトピックの言い回し)にすり替わっており、「荷物が届いたか」という本来の質問には答えていない。detail応答の時点(2ターン目)からすでに意味が破綻している。

### N3: スマホの修理
```
User: スマホの画面が割れちゃって、修理に出したんだ
Lilas: それは大変ですね、無理なさらないでくださいね。
User: 修理には1週間くらいかかるって言われたよ

User: お気に入りのカフェが新しくオープンしたんだ

User: そういえば、修理に出したスマホ、戻ってきた?
Lilas: 迷っていらっしゃったスマホですね、その後いかがですか?
```
**判定: △ 部分(良好寄り)。** 固有の対象語「スマホ」は正しく再言及できている。ただし「迷っていらっしゃった」(買うか迷っていた、という買い物トピックの型)を流用しており、「修理に出して戻ってきたか」という本来の意味にはなっていない。対象語の保持は新形状の中では比較的良い方。

### N4: サプライズパーティーの計画(内緒にする)
```
User: 友達の誕生日にサプライズパーティーを計画してるんだ
Lilas: それは楽しみですね。
User: 本人には内緒で、みんなでケーキを用意することになってるんだ

User: そういえば、あのサプライズの計画、うまく進んでる?
Lilas: 大事なサプライズのサプライズですね、うまく進んでいらっしゃいますか?
```
**判定: ✕ 失敗(表面的には整合)。** detail応答の時点で「お菓子の詰め合わせ」「同僚様との再会」など全く無関係なプレゼント/歓迎会トピックのスロットが混入し、完全に意味が破綻している。呼び戻し自体は「サプライズのサプライズですね」とユーザーの単語をそのままオウム返ししているだけで、実質的な理解は伴っていない(語彙が訓練データに存在しないため、コピー機構で表面をなぞっているだけ)。

### N5: トマトの虫害(「育て始めた」ではなく問題対応形)
```
User: 庭のトマトの葉っぱが虫に食われてるのを見つけたんだ
Lilas: それは驚きましたね、お怪我はありませんでしたか?
User: とりあえず虫を手で取って、様子を見てるところなんだ

**判定: ✕ 失敗。** 「トマト」という語は保持されるが、ペットトピックのテンプレート(「{age}の{name}ちゃんですね、お元気だとよいのですが」)がそのまま適用され、「1歳のトマトちゃん」という意味不明な文になっている。植物の"世話を始めた"形状はあっても"虫害トラブル"形状は訓練に無いため、最も近い「心配される生き物」テンプレート(ペット)に誤って吸着している。

### N6: 転職先の2社で迷う
```
User: 実は転職先の候補が2社に絞られたんだ
Lilas: それは大きな決断ですね。

```
**判定: △ 部分。** 「1社」「給料」という具体的な語彙は保持されているが、文としては論理が破綻している(「給料が分からないから自信を持って臨める」は意味が繋がらない)。二択の意思決定という構造は訓練データに存在しない(訓練の"迷ってる"形状は単一の商品/サービスへのYes-No)。

```

**判定: ✕ 失敗。** 導入時点の反応(「それは楽しみですね!」)からすでに的外れ(困っている報告に対して"楽しみ"の反応)。呼び戻しでは料理トピックの callback_a(「美味しくできましたか?」)がそのまま流用され、無くしたボールの話とは無関係な文になっている。「物をなくして探す」という構造は訓練に存在しない。

## パターンのまとめ

**1. 訓練済み形状(24種)そのものは、雑談4個を挟む深い呼び戻し(N15)でも安定して機能する。**
C2(ペット名)・N15(ボルダリング、雑談4個)は固有名詞や数値詳細まで正確に再言及できた。「callbackスキルが8回連続で機能した」という既存の確認は、少なくともこの現行チェックポイントでも再現される。

**2. 新規トピック形状は、浅い呼び戻し(雑談1〜2個)でも高確率で崩壊する。距離(ターン数)は主要因ではない。**
N14(傘・雑談4個・新規形状)は完全崩壊、N15(ボルダリング・雑談4個・訓練形状)は完全成功——**同じ距離**で結果が正反対。逆にN5・N7・N9・N16のような雑談1〜2個の**浅い**新規形状も軒並み失敗している。したがって「呼び戻しの成否を決めるのはターン数ではなく、トピックの構造が訓練済み24種のどれかに十分近いかどうか」という結論になる。

**3. 新規トピックに対する失敗モードは「無回答」ではなく「最も近い訓練済みテンプレートへの誤った吸着」である。**
- トマトの虫害 → ペット安否確認テンプレート(「1歳のトマトちゃんですね」)
- なくしたボール → 料理の callback_a(「美味しくできましたか?」)
- スマホの修理 → 商品購入検討テンプレート(「迷っていらっしゃったスマホ」)
- 荷物の配送待ち → 引き継ぎ/取引先対応テンプレート(「担当者様へのご連絡」)
モデルは「わかりません」と正直に答えるのではなく、語彙的・構造的に一番近い訓練済みパターンを流用して**流暢だが意味の崩れた文**を生成する。これは40Mパラメータの小規模モデルが「未知の構造には対応できないが、それを検知して保留する能力(calibration)も持たない」ことを示している。

**4. 数値・日時の呼び戻しは、トピックの新規性と無関係に一貫して失敗する。**
N8(集合時間9時)・N9(カップケーキ35個)はいずれも数値を一切再現できなかった。N9では呼び戻し質問の言い回し(「何個注文したんだっけ?」)が計算ツールのトリガーと干渉したとみられる不自然な逆質問(「もし2個買うと合計いくらになる?」)まで誘発している。訓練データの24形状の中にも数値そのもの(日付・年齢・金額・個数)を挟む話題はあるが、callback_aのテンプレートは基本的に固有名詞(人名・地名・トピック名)を再言及する構造であり、数値を答えの中核に置く callback は訓練データの構造上そもそも薄いと考えられる。これは新規性の問題であると同時に、既存の訓練データ設計自体の穴でもある。

**5. 「直近バイアス」による誤参照が新規トピックで目立つ(N12)。**
呼び戻しフレーズ(「そういえば」)自体は正しく認識されるが、参照先を数ターン前の本来のトピックではなく、直前の雑談ターンに誤って結びつけるケースが見られた。訓練データでは雑談は必ず1〜2個で、直後に呼び戻しが来るため、モデルは「そういえば」の後に来る話題を"直前の1ターン前"に紐づける弱い相関を学習している可能性がある。新規トピックでは元の話題への強い結びつきが無いため、この弱い相関が表面化しやすいと考えられる。

**6. 部分成功にも段階があり、「固有名詞・特徴的な語彙の保持」は新規トピックでも比較的起きやすいが、「発話全体の論理・時制の一致」はほぼ常に崩れる。**
N3(スマホ)・N6(2社/給料)・N13(先週受けた試験)は名詞句をほぼ正確に再言及できているが、いずれも文全体としては論旨がズレている(未来のことのように聞いたり、無関係な相槌で終わる等)。つまり「表層的な語の保持」と「意味的に正しい応答の生成」は別々に汎化しており、前者の方が後者よりわずかに汎化耐性が高い。

### 結論
callbackスキルは訓練済み24形状(とその近い変種)に対しては、ターン距離が伸びても頑健。しかし構造的に新規な話題(物の紛失、進行中のトラブル対応、二択の意思決定、結果待ち、数値・時刻の記憶)に対しては、浅い距離でも高確率で失敗し、失敗の大半は「最も近い訓練済みテンプレートの誤った流用」という形で現れる。これは記憶(memory)ではなく汎化(generalization)の失敗であり、追加の訓練データにはこれらの新規形状(特に数値記憶・対象物の紛失・進行中の問題解決)を明示的に加える必要があることを示している。
