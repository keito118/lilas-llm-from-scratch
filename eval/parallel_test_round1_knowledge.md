# 知識・事実質問の並行テスト(Round 1)

チェックポイント: `checkpoints/lilas.pt`(デフォルト)
実行方法: `lilas.chat.generate_reply` を直接呼び出し(`--once`ではなく履歴を持たせたループ)。
temperature=cfg.temperature(0.8)のまま、既知の質問(エベレスト、富士山、織田信長、琵琶湖、Python等)は避け、
未テストの質問を中心に37件(単発31件+複数ターン往復6件)を実施。

凡例(検証結果列): 正解 / 妥当(未検証) / 誤情報 / 無関係な幻覚 / 文脈無視 / ツール未発火(発火すべき)

## パターンのまとめ

1. **人口の質問は「ツール発火はするが、人口の数字自体が本文に見つからないと丸ごと的外れな説明文にすり替わる」が最も典型的な失敗**(#18, #21)。ときには単位混同(人口→面積km2、#20)、ときには捏造数値(#22)というように失敗の"形"自体が毎回変わる。学習データとしては、「人口が見つからない場合にどう振る舞うべきか」(例:「詳しい人口は分かりませんでした」のような正直な返答)を明示的に教える必要がある。

2. **「〜とは誰/って誰」の人物質問は、時代区分だけを答えて人物の正体(役職・業績)に触れない、もしくは近接する無関係な文を人物の正体として誤答する傾向が強い**(#13, #14, #15, #16, #17)。特に#16(紫式部→武将・大名・貴族院議員)と#17(坂本龍馬→江戸幕府初代将軍)は、注入された参考情報とは無関係な、性別や時代を無視した完全な幻覚テンプレートを生成しており、womanic figureや幕末人物に対する訓練データの偏り(男性の武将テンプレートへの引き込まれ)を示唆する。

3. **「の首都は?」「の距離」「の値段」「どうやって〜」「いつ〜した」は現行の`_KNOWLEDGE_TRIGGERS`に一切対応しておらず、これらのフレーズは常にツール未発火で生の生成に落ちる**(#12, #33, #34, #36, #37)。特に「の値段」「の距離」は、たとえツールが無くてもモデルが calculator 的な出力テンプレート(「X円×Y=Z円」)や無関係な人口統計を捏造で埋めてしまう傾向が強く、単なる「答えられません」より悪い(自信満々に誤情報を出す)結果になっている。「どうやって」は既知の事実(富士山の標高など)にすり替わる形で誤魔化す。

4. **同じ質問を2回試すと、失敗の"種類"自体が変わるほどフレーキー**(#3/#6の単位違い、#18/#21の反復バグ有無、#20/#22の誤情報のパターン違い)。これは「注入された参考情報をどう使うか」がモデル内でまだ安定していないことを示しており、1回のテストで「直った」と判断するのは危険。

5. **複数ターンでは、直前ターンで自分が正しく言った数値を次のターンで平気で言い直して矛盾させる**(#27-28: 333m→670フィート)、または質問の文脈もツールが注入した事実も両方無視して自己言及的な無関係文を返す(#29-30)。単発では出せていた正しい事実(東京タワー333m)が、フォローアップ質問(比較・言い換え)が絡むと急激に崩れる点は、フォローアップ質問形式(「じゃあ〜と比べて」「その人は〜」)専用の学習データが手薄であることを示している。

6. **detail_pattern(高さ用の数字パターン、はどこ用の都道府県パターン)が想定外の質問(建物によって高さの記述場所が違う、聞かれているのが「県」ではなく「島」など)にマッチしないと、ツールは"発火"しているのに実質的に無回答の説明文だけを返す**(#2: あべのハルカス、#11: 日本で一番大きい島)。ツールが「見つからなかった」ことを明示的にNoneとして扱えていないケースがあり、「参考情報はあるが的を外している」中途半端な注入がむしろモデルの幻覚を誘発している可能性がある。
