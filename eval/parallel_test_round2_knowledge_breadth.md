# 知識トリガーの網羅性 + 回答品質 並行テスト(Round 2・広範囲版)

チェックポイント: `checkpoints/lilas.pt`(round2タグ、現行本番)
実行方法:
- トリガー層のみの高速チェック(`_extract_search_query` / `_looks_like_question` を直接呼ぶ、モデル不要)を約70件
- そのうちツールが発火する知識質問24件+誤発火疑いの4件について、`generate_reply()` をフル実行してモデルの最終出力まで確認

前提: `lilas/tools.py` を事前に読み、2026-09-10時点で追加済みの
`の首都/の国旗/の通貨/の国歌/の距離/の値段/は何県/はいつ/は何ですか/ってどんな人/の意味`
を把握した上で、**それでもまだ拾えない**新規フレーズと、**広すぎて誤発火する**フレーズの両方を探した。

凡例: ○=トリガー発火した(≠正しい答えとは限らない) / ×=未発火

### 推奨する追加パターン(既存コードと同じスタイルで)

優先度が高い順:

```python
# 「〜の県庁所在地は?」(「どこ」省略形。既存の「はどこ」より頻度が高いと思われる)
(re.compile(r"(.+?)の県庁所在地"), "where", re.compile(r"[^\s、。]{2,6}[都道府県]")),

# 「〜を知ってる?」「〜について知ってる?」
(re.compile(r"(.+?)(?:について)?を?知ってる"), "what", None),

# 「〜ってどういう意味?」(「の意味」の口語バリエーション)
(re.compile(r"(.+?)ってどういう意味"), "what", None),

# 「〜の面積は?」(高さ・人口と同型の数値抽出が使える)
(re.compile(r"(.+?)の面積"), "what", re.compile(r"面積[^\d]{0,12}[\d,]+(?:\.\d+)?\s*(?:km2|平方キロ)")),

# 「〜の寿命は?/の平均寿命は?」
(re.compile(r"(.+?)の(?:平均)?寿命"), "what", None),
```

「の正式名称」「の読み方」「の色」「の直径」「の税率」「のルール」「はいくつある」は発生頻度・実装コストとのバランスで次点。
「AとBどっちが〜」の比較質問は、正規表現1本では2エンティティを跨いだ知識取得ロジックが必要になり構造変更が大きいため、今回は「既知の限界」として記録するに留める。

## 2. 誤発火(false positive)の疑いがある既存パターン

タスクの想定通り、**広い「Xはいつ」「Xは何ですか」パターンが日常会話の一部を誤って知識質問として拾ってしまう**ケースを複数確認した。`_looks_like_question`(?や「だっけ」等の語尾)は通過してしまう、ごく自然な口語文で発生する。

| # | 入力文 | 発火 | 抽出クエリ | 実際にモデルまで通した結果 |
|---|---|---|---|---|
| 19 | 会議はいつ終わるんですか? | ○ | 「会議」 | **誤発火を確認**。Wikipediaの一般名詞「会議」の定義文が注入され、モデルは「会議は、各議題に対する準備と責任を指します。…全員が同じ日に会議を終了することを保証することです」という、質問(終了時刻)に無関係かつ意味不明な文を生成。「はいつ」は疑問詞の直前が固有名詞かどうかを区別できていない。 |
| 20 | 宿題はいつ出すんですか? | ○ | 「宿題」 | 同様に誤発火。Wikipediaの「宿題」定義(日本の学校教育の節)が注入され、モデルは「はい、こちらは基本的な学習スタイルの一部です。」という論点のずれた返答。 |
| 21 | これは何ですか? | ○ | 「これ」 | **重大な誤発火**。「これ」という代名詞でWikipedia検索した結果、全く無関係なブラウザゲーム『艦隊これくしょん -艦これ-』(通称「艦これ」)がヒットし、それが注入される。モデル出力は「『Wikipedia -艦これ-について…ブラウザは配信している日本の育成シミュレーションゲームおよび配信サービスです。」という完全に破綻した文。`_is_self_reference`は「あなた/君/お前」等は弾くが、「これ/それ/あれ」のような指示代名詞は対象外になっている。 |
| 22 | 君の名前は何ですか? | ○ | 「君の名前」 | **重大な誤発火**。「君の名前」というクエリが、槇原敬之のシングル曲「君の名前を呼んだ後に」にヒットし、モデル出力は「IKE BLE(2004年5月21日生まれ)、MTV Classics We Areath…」という存在しない人名・日付を羅列した完全な幻覚。Lilas自身への「名前は?」という定番の質問がまさかの音楽記事に誤爆する。 |

### 推奨する対処

- `_is_self_reference` / `_SELF_REFERENCE_BASE` の対象を「これ/それ/あれ/この/その/あの」等の指示語、および「名前」を含む自己言及クエリ(「君の名前」「あなたの名前」等)にも広げる。
- 「Xはいつ」「Xは何ですか」の2パターンは、`X`が1〜2語程度の一般名詞(辞書的な語)の場合に誤爆しやすい。`X`の長さや、後続に「んですか/出す/終わる/来る」のような動詞的述語が続く場合(=Xが主語であって聞きたい対象ではない)を除外する追加条件が有効そう。例えば「Xはいつ+動詞」の場合は「Xについて」ではなく「動詞の時刻」を聞いているため、現状の実装だと原理的に答えようがない質問を無理に拾ってしまっている。

一方、明確な非質問文(「今日はいつもより早く起きた」「値段はいつも通りだった」「彼女は誰よりも優しい人です」等)は`_looks_like_question`の語尾チェックで正しく弾かれており、そちらは問題なし。

### カテゴリ別の傾向

1. **「Xとは/って何」型の単一概念の定義質問が最も強い**(メートル、キログラム、パンダ、DNA、量子力学、徳川家康、織田信長)。Wikipediaの導入文がそのまま定義として使える場合、モデルはほぼ忠実に言い換えられる。人物のwho型も、直接の伝記記事でなくても(徳川家康は「江戸幕府」の記事から抽出)意外と正確に答えられている — これはRound1(2026-09-09時点)の報告(「who型は時代区分だけ答えて人物の正体に触れない」)と比べて明確に改善している。
2. **「本文の中から特定の数値・固有名詞を1つ拾い出す」必要がある質問(首都名、人口数値、県庁所在地、県名)が最も弱い**。コンテキストに答えがちゃんと含まれているのに(#1 富士山の高さ、#9 滋賀県庁所在地、#19 マラソンの距離)、モデルが無視するか、全く無関係な数字を幻覚するケースが目立つ。特に#19(マラソン距離)はコンテキストに42.195kmと明記されているにもかかわらず「男子456キロ、女子270km」という荒唐無稽な数値を生成しており、**「コンテキストにある正しい数字より、もっともらしい別の数字を生成する」傾向がRound1から継続している既知の弱点**だと分かる。
3. **通貨(#21, #22)は構造的にほぼ確実に失敗する**。「の首都/の国旗/の通貨/の国歌」は`try_knowledge`側で同じ`"what"`種別・`detail_pattern=None`として扱われているが、国の記事の冒頭2文には通貨の記述がほとんど含まれない(首都は含まれることが多い)。首都は運が良ければ当たるが、通貨は今回のサンプルでは2/2とも本文に情報が無く、必然的に質問に答えられていない。**トリガー自体は発火しているが、ツールが実質的に「無回答用のダミー情報」を注入しているだけ**になっており、高さ・人口のような専用detail_patternを通貨にも用意しない限り改善しない。
4. **検索語が短い・一般的すぎると全く違う記事にヒットする**(#17「ドラえもん」→「ドラえもん映画作品」)。これは2節の「これ」「君の名前」の誤爆と同根の問題で、Wikipedia検索APIの`srlimit=1`(最上位1件のみ採用)が短い語ではノイズを拾いやすい。

## まとめ(優先度順)

1. **誤発火対策(最優先)**: 「これ/それ/あれ」等の指示代名詞と「名前」絡みの自己言及クエリを`_is_self_reference`相当の除外対象に追加する。「Xはいつ/Xは何ですか」の2パターンは、Xが後続の動詞の主語にすぎない(「会議はいつ終わる」「宿題はいつ出す」)日常文を誤って拾ってしまうため、X直後に動詞的な述語が続くケースを除外する条件を追加する。
2. **新規トリガー**: 「〜の県庁所在地は?」(どこ省略形)、「〜を知ってる?/について知ってる?」、「〜の面積は?」、「〜の寿命は?」を追加。特に県庁所在地の「どこ」省略形は既存の「はどこ」パターンの単純な穴であり、実装コストが低く効果が高い。
3. **ツールの中身の改善**: 「の通貨」トリガーにも高さ・人口のようなdetail_pattern(通貨名を本文から探す正規表現)を追加しない限り、通貨質問は構造的にほぼ100%失敗し続ける。
4. **モデル側の既知の弱点(トリガー修正では直らない)**: コンテキストに正しい数値が明記されていてもそれを無視して別の数値を幻覚する傾向(#1, #19)、複数の断片をつなぎ合わせる際に主語と述語が逆転する傾向(#24)は、トリガー・検索ロジックの外側にあるモデル自体の課題として別途記録する。
