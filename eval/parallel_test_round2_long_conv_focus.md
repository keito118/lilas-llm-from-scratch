## 1. 長さのしきい値: 5→7ターンの間で明確に崩れる

「引っ越し」を軸にした同一構造の会話(A1〜A6)で長さだけを振った結果:

- **3〜5ターン**: 質問のキーワード(スーパー/新居)自体は応答に残る。答えにはなっていない(オウム返しや不自然な一人称化)が、少なくとも「何について聞かれたか」は捉えている。
- **7ターン以上**: 完全に一般論の労いフレーズか、話題すり替えテンプレートに置き換わる。8ターン(=既知の失敗ケースの会話18)で再現に成功、10・12ターンではさらに典型的な「ターン1話題への回帰」パターンが明確に出た。

`final_history_token_count`(トークナイザでのプロンプト長)は3ターンで約100、5ターンで約141、7ターンで約213、12ターンで約321。block_size=1024に対しては常に余裕があり、**`model.py`の`idx_cond = idx[:, -self.cfg.block_size:]`によるハードな切り詰めはこの範囲では一切発生していない**(コード上確認済み・実測トークン数でも確認済み)。つまり「物理的に古いターンが見えなくなる」ことが原因ではない。しきい値はトークン長ではなく**ターン数(構造的パターン)**に強く相関している — これは後述の学習データの構造(数ターン往復+末尾の呼び戻し質問という「型」)と一致する。

## 2. 感情的に重い前置きターン vs 中立な雑談: 意外にも「重い」方が良い結果だった

B1(8ターン・祖母の入院という重い話題を挟む)は、同じ長さ・同じ最終質問のA4(中立な雑談を挟む、既知の失敗ケース)よりも**良い結果**だった。A4は話題をすり替えて無視したが、B1は「その周りを探してみたところ、分かりかねます」と、分からないなりに質問の内容(スーパー)に触れて応答できた。

考えられる理由: A4系列は序盤〜終盤まで一貫して「引っ越し」に関連する話題(物件探し/部屋/段ボール/荷造り)が繰り返されるため、「引っ越し」という話題の顕著性(saliency)が積み上がり続ける。一方B1は「引っ越し」と「祖母の入院」という**二つの異なる話題が拮抗**するため、どちらか一方に強く引っ張られる力が弱まり、結果的に最終ターンの内容がモデルの出力に反映されやすくなった可能性がある。ただし12ターンまで長さを伸ばすと(F2)感情負荷ありでも最終的にはターン1回帰の失敗に転じており、**感情負荷そのものが防御にはならず、長さが最終的に支配的な要因になる**ことも確認した。

なお、B1・F2・G1(感情負荷あり)では、中間ターンで「それは大変そうですね、無理なさらないでくださいね。」のようなほぼ同一の労いフレーズが**非連続なターンにまたがって繰り返される**現象が目立った。`lilas/chat.py`の`_extract_last_reply`/`extra_penalize_ids`は**直前1ターンの返答トークンにしかペナルティをかけない**(`chat.py` L74-93, L124, L135-139のコメント参照)ため、2ターン以上前の返答と同じフレーズを再度選ぶことは抑制されない。これは今回調査した「質問を無視する」バグとは別系統の問題だが、同じ「感情の反響に囚われる」現象の一部として現れており、根本原因が共通する(強く学習された定型フレーズへの引力)可能性がある。

## 3. 最終質問の関連性(自然な継続 vs 話題転換): 決定的な要因ではなかった

7ターンで比較(A3=自然な継続 vs C1=完全な話題転換)すると、**どちらも失敗**し、しかも失敗の質もどちらも「無関係な労いの定型文」で似通っていた。話題転換だからといって明確に悪化するわけではない。

むしろ短い会話では話題転換の方がうまくいった例すらある: F1(3ターン、猫と犬どちらが賢いかという完全な話題転換)は「どちらも違った賢さがあると思います。猫は独立心が強く、犬は人と協調する賢さに長けている」というまとも回答を返した。G1(8ターン・感情負荷+話題転換)では、テンプレート自体は誤爆した(「新しい恋愛ドラマのお話ですね」)ものの、**すり替え先がターン1の話題(引っ越し/祖母)ではなく、最終質問自身の話題(ドラマ)だった**。これは後述の「テンプレート誤爆」仮説を裏付ける: 誤爆するテンプレートが挿入する名詞は「一番古い話題」に固定されているわけではなく、**プロンプト全体の中で最も顕著な名詞句**に引っ張られる。長い雑談部分が単一トピック(引っ越し)で埋め尽くされていればそれが顕著になり、最終質問自体の名詞が十分特徴的(「ドラマ」)であればそちらが顕著になることもある。

## 4. 「ターン1回帰」なのか「ただの汎用応答」なのか: 両方あるが、原因は同一のテンプレート機構

明確な「ターン1(または序盤)の話題への回帰」が確認できたのは A5, A6, E2, F2 (いずれも8〜12ターン、話題が一貫している会話)。これらはすべて **`「Xのお話でしたね、Y?」という固定テンプレート構文**で発生しており、Xに序盤の話題語(新居/手作りパスタ)、Yに定型の様子伺い文(「準備は進んでいますか」「美味しくできましたか」)が入る。

一方、A3・C1・D2のような「ただの汎用応答」に見えるケースも、詳しく見ると**別カテゴリの学習データのテンプレートがそのまま漏れ出している**ことが分かった(下記セクション5)。つまり「ランダムに何か無関係なことを言っている」のではなく、**毎回、どこかの学習データテンプレートに"落ちて"いる**という共通点がある。これは的外れな応答の原因が単一ではなく、プロンプトに含まれる語彙がどの学習データの型にマッチするかによって複数の失敗モードに分岐する、という構造を示している。

## 5. 学習データを突き合わせた結果: 「7件では足りない」は事実だが、それ以上に構造的な原因がある

`scripts/generate_emotion_data.py`のLONG_CONV_FOCUS(6件、`index/generated_emotion_ja.txt`内、ファイルサイズ約11KB)は、実は**同じ「複数ターン会話+末尾の呼び戻し質問」という構造を、真逆の目的で大量に学習させている`index/generated_longcontext_ja.txt`(約190KB、`scripts/generate_longcontext_data.py`が生成)と真正面から競合している**ことが分かった。

```
$ grep -c "のお話でしたね" index/generated_longcontext_ja.txt
106
$ grep -c "^User:" index/generated_longcontext_ja.txt
1403
```

`generated_longcontext_ja.txt`には「Xのお話でしたね、Y?」という**まさにテスト結果で誤爆したのと同一の構文**が106件も含まれ(例: `引っ越しのお話でしたね、準備は進んでいますか?`、`パスタのお話でしたね、美味しくできましたか?`、`水槽のお話でしたね、掃除は済まされましたか?`)、しかも実際にA5(「新居のお話でしたね、準備は進んでいますか?」)やE2(「手作りパスタのお話でしたね、美味しくできましたか?」)で出力された文言は、この学習データの中の実例(`引っ越しのお話でしたね、準備は進んでいますか?`/`パスタのお話でしたね、美味しくできましたか?`)と**ほぼ一字一句一致**している。

このテンプレート自体は本来「callback(数ターン前の話題を呼び戻す)」を学習させるためのもので、`scripts/generate_longcontext_data.py`のdocstringにも「複数ターン会話(callback形式)をテンプレート+スロット埋めで大量生成」と明記されている。「そういえば、あの件どうなった?」のような**状態確認型の呼び戻し質問**に対しては、このテンプレートは本来正しい。しかし今回のテスト対象である「新居の近くにスーパーがあるか」のような**新規の具体的情報を求める質問**に対しても同じテンプレートが誤爆しており、モデルは「長い会話の末尾に質問が来た」という表層パターンだけで「callback応答すべき状況」と誤判定している。

LONG_CONV_FOCUS(6件)は、この誤判定を修正するために作られた対抗データだが、**106件 vs 6件という数の差は17倍以上**であり、かつ106件側は`generate_longcontext_data.py`のdocstring自身が「過去にテンプレートの固定フレーズが無関係な文脈に漏れ出す問題(テンプレート漏れ)が起きた」と明記しているほど強く定着しやすい構文である。6件程度の追加データでこの学習済みの強い傾向を上書きするのは、量的に見て端から不利な戦いだったと言える。これは`training_log.md`の2026-09-09の記録(「少量(1桁〜10件程度)の追加データでのピンポイント修正は、狙った箇所以外のバランスを崩すリスクがある」「次回はもっとまとまった量で試すか」)とも一致する、このプロジェクトで繰り返し観測されているパターンそのものである。

さらに、D2・D3・E1の結果は、テンプレート誤爆が「callback構文」だけに限らないことを示している:

- **D2**(結婚式の設定+新しい質問「ご祝儀の相場」)への応答「そうですか、無理にまとめなくても大丈夫ですよ。」は、`generate_emotion_data.py`内の**曖昧入力用テンプレート**(`AMBIGUOUS_REPLIES`)の文言と一字一句同一。具体的で答えられるはずの質問を、モデルが「曖昧な入力」に誤分類したことを示す。
- **D3**(実家の犬の設定+新しい質問「ストレスのサイン」)への応答「犬は哺乳類の一種である。」は、会話データには存在しない文体で、`index/external_aozora_ja.txt`(青空文庫の文語調コーパス)に大量に出現する「〜は…の一種である。」という言い回しと酷似している。「犬」という単語がこの文語コーパスの言い回しを誘発したとみられる。
- **E1**(転職面接の設定+「スーツで大丈夫か」)への応答「スーツの方は体が軽く、吸引力が強いですね。」も同種の、キーワード単発トリガーによる意味不明な生成。

つまり実際に起きているのは「長い会話だと直近の質問への注意が単調減衰する」という漠然とした注意機構の問題ではなく、**プロンプト中の特定の語(名詞)が、それぞれ別々の巨大な学習データ塊(callbackテンプレート/曖昧入力テンプレート/文語コーパスの言い回し)を強く誘発し、モデルがそちらの「型」に飛び移ってしまう**という、複数の競合する強いアトラクタ(学習された定型パターン)の問題である。LONG_CONV_FOCUSはそのうち1つのアトラクタ(callbackテンプレート)にしか対抗しておらず、しかも量が全く足りていない。

## 結論

1. **しきい値は概ね5〜7ターンの間**。3〜5ターンでは質問の対象語だけは反応に残るが、7ターン以上でほぼ確実に一般論または誤ったテンプレートに落ちる。8ターン(既知の失敗例)、10・12ターンで顕著な「序盤話題への回帰」が再現した。トークン長(実測100〜324、block_size=1024の範囲内)は原因ではない — `model.py`のblock_size切り詰めはこの範囲では発火していない。
2. **感情的な重さは主要因ではない**。むしろ今回のテストでは感情負荷ありの方が良い結果になる場合があった(単一話題が長く続くほど、その話題の顕著性が積み上がって誤爆しやすくなるという方が説明力が高い)。
3. **最終質問の関連性(自然な継続か話題転換か)も決定的要因ではない**。同じ長さなら両方失敗し、失敗の質も似ている。
4. **「ターン1回帰」は実在するが、それは注意の減衰ではなく、特定の学習済みテンプレート(callback応答)が誤発火した結果**。誤爆する名詞は必ずしもターン1固定ではなく、プロンプト中で最も顕著な名詞句(会話が単一話題で埋まっていればターン1の話題、そうでなければ最終質問自身の話題になることもある)。
5. **7件(実際は6件)という量は構造的に不十分**。競合する学習データ(`index/generated_longcontext_ja.txt`)には同一構文が106件含まれており、量的に17倍以上の差がある。加えて、失敗パターンはcallbackテンプレートだけでなく、曖昧入力テンプレートや文語コーパスの言い回しへの誤爆も含む複数系統であり、LONG_CONV_FOCUSはそのうち1系統にしか対処していない。

**次の一手への示唆(参考、今回はコード変更なし)**: (a) LONG_CONV_FOCUSの件数を大幅に増やす、または既存の`generated_longcontext_ja.txt`側に「callbackすべきでないケース(新規の具体的質問)」を同程度の量で混ぜて対比学習させる。(b) `extra_penalize_ids`を直前1ターンだけでなく直近数ターンの返答語彙に広げることで、非連続ターンでの定型句の使い回しを抑制できる可能性がある(ただし今回発見した主要因ではない)。(c) 学習データの出典(文語調コーパス/曖昧入力テンプレート/callbackテンプレート)ごとに文体マーカーが薄いため、モデルが語彙一致だけで別ジャンルに飛び移りやすい構造そのものを見直す余地がある。
